# R05 指摘事項 対応記録

- 対応日: 2026-09-02
- 対象: [`r05-2026-09-02-review-finding.md`](r05-2026-09-02-review-finding.md)
- 結果: **Critical 1 件と、実装側の指摘をすべて対応**。ドキュメントは別途整備中
- 検証: Release / 負荷下 / ASan / UBSan / TSan の全構成で **144/144 PASS**

## 総括

R05 が捕まえたのは、R01〜R04 の 4 回では出なかった 2 種類の問題である。

### 1. 別々に正しい 2 つの修正が、重なったときだけ壊れる

R04-F08（`PTHREAD_PRIO_INHERIT`）と R04-F23（`pthread_mutex_clocklock`）は
**単独ではどちらも安全**で、両方入れたときだけプロセスが `SIGABRT` で落ちる。
しかも TSan ビルドではスピン待ちにフォールバックするため**原理的に検出できず**、
138/138 が緑のまま潜んでいた。

「個々の修正を検証する」だけでは足りず、**修正どうしの相互作用**を見る必要がある、
という教訓である。

### 2. 回帰テストが「たまたま通っていた」

`SHM_DECLARE_LAYOUT` が塞ぐと謳った当のケース（同サイズのメンバの並べ替え）を
検出できていなかったが、テストに使った 2 型のサイズが違ったため偶然オフセットが
ずれて検出でき、緑になっていた。

R03 で「テストが機能を守れていない」と指摘されたのと**同じ失敗の再発**である。
R04 以降は「修正を巻き戻すと落ちる」注入実験を必ず行うようにしたが、
それは**バグを入れた側**の検証であって、**テストが対象を正しく突いているか**は
別に確かめる必要があった。

## 対応

| ID | 深刻度 | 対応 | コミット |
|---|---|---|---|
| Critical-1 | Critical | `PRIO_INHERIT` を外し、待ち方を `trylock` + `nanosleep` に | `496b363` |
| R05-F01 | High | ハッシュにメンバ名と型の指紋、入れ子型の宣言を畳み込む | `e85e0cc` |
| R05-F02/F03 | High | 隙間の許容量を「オフセットを割り切る最大の 2 冪」に | `e85e0cc` |
| R05-F04 | High | 世代タグが未公開なら誰でも CAS で公開できるようにする | `e85e0cc` |
| R05-F05 | Medium | `doctor` を `RingBuffer::inspectLayout()` 経由にする | `e85e0cc` |
| L1 | Low | `createNextGeneration()` の失敗経路でも解放する | `e85e0cc` |

### Critical-1 — 待ち時間つきロックをやめる

対策を 2 つ入れた。

1. `PTHREAD_PRIO_INHERIT` を設定しない
2. 待ち方を `trylock` + `nanosleep` に変える

**2 が要点**である。`trylock` は壊れた futex ワードでも `EBUSY` を返すだけなので、
**古い PI 付きのセグメントが残っていても落ちない**。1 だけでは、既に作られた
セグメントの mutex が PI のままなので守れない。

R04-F23 が直した「CPU 過負荷のとき保持者に CPU が回らない」問題も再発しない。
当時の原因は `sched_yield` が自分の量子を捨てるだけだったことで、実際に眠れば解消する。
負荷下 25 回中の publish 失敗は **0**、負荷下の全スイートも 5/5 PASS。

優先度継承は失われるが、待ち時間つきロックを使わない以上どのみち働かない
（`trylock` は優先度を押し上げない）。スロットが取れなかった場合は例外／再試行で
表面化するので、`SIGABRT` との比較では明らかに安全側である。

### R05-F01 — 何を畳み込むべきだったか

位置と大きさだけでは、レイアウトの違いを表せない。

| 変更 | offsetof | sizeof | alignof | 検出に必要なもの |
|---|---|---|---|---|
| `{x,y,theta}` → `{theta,x,y}` | 同じ | 同じ | 同じ | **メンバ名** |
| `float v` → `int32_t v` | 同じ | 同じ | 同じ | **型の性質** |
| 入れ子 `{x,y}` → `{y,x}` | 同じ | 同じ | 同じ | **入れ子型自身の宣言** |

型の識別に `type_schema_id<T>()`（`__PRETTY_FUNCTION__` の hash）は使えない。
ツールチェインが違うと別の値になり、コンテナとホストで通信できなくなる。
代わりに「整数か浮動小数点か」「符号の有無」「大きさ」「境界」「配列か・要素数」
といった**移植性のある性質**から指紋を作る。`float` と `int32_t` は
`is_floating_point` で区別できる。

入れ子型は `shm_schema<Element>::version` を畳み込む。そのため
**入れ子の型は外側より前に宣言する**必要がある（外側の宣言で実体化されるため）。
型の定義の隣に宣言を置いていれば自然に満たされる。

### R05-F02/F03 — 隙間の許容量

`alignof(decltype(T::m))` を使ってはならない。`decltype` は素の型を返すので
**メンバ宣言に付けた `alignas` を拾わない**。無名共用体も同様で、代表として
並べたメンバの境界は共用体全体の境界と一致しない。

実際のオフセットを割り切る最大の 2 冪（`offset & -offset`）を、型全体の境界で
頭打ちにしたものを許容量とする。これなら宣言に何が書いてあっても
「そこに置くために必要だった調整」が分かる。

```
struct { char a; alignas(16) int b; }   offset(b)=16 → 許容 16、隙間 15 → 通る
struct { uint32_t a,b,c; } で b を書き漏らし  offset(c)=8 → 許容 4、隙間 4 → 弾く
```

## 検証

```text
Release            : -j1 x4 / -j4              144/144 PASS
Release（CPU 負荷下）: 全スイート x5             144/144 PASS
ASan / UBSan       :                            143/143 PASS
TSan（setarch -R） : x2                         143/143 PASS
```

サニタイザ構成が 1 件少ないのは Python バインディングのテストを登録しないためである。
外部特殊化は lidar / point_cloud の回帰スイートを ASan+UBSan で 5/5 PASS、
cv は構文チェックで確認した。

### 注入実験

| 注入 | 結果 |
|---|---|
| `PRIO_INHERIT` と `clocklock` を戻す | 1 件 **Subprocess aborted** |
| ハッシュからメンバ名・型の指紋を外す | 3 件 FAIL |
| 隙間の許容量を `alignof(decltype(T::m))` に戻す | 2 件 FAIL（正しい宣言が弾かれる） |
| `doctor` の `inspectLayout()` 経由をやめる | 1 件 FAIL（破壊注入 6 種） |

### テストの前提を実態に合わせたもの

`buffer_num = 1` に依存していたテスト 2 本を整理した。
`ShortCriticalSections…` は publish 失敗を数えて報告するだけにし、
`FailedSubscribeMustNotCorruptPreviousValue` は確率に頼るのをやめて、
**外からスロットの mutex を保持して決定的に失敗を作る**形にした。
TSan では読み出し失敗が 1〜49 回まで減っており（Release では 20 万回）、
前提の `ASSERT_GT` が空振り寸前だった。

## 未対応（今後の改善項目）

R05 の Low 指摘のうち、次は今回対応していない。

| ID | 内容 | 判断 |
|---|---|---|
| L2 | `migrateHistory` のスナップショット後・CAS 前に旧世代へ commit した publisher が再発行しない | 容量拡張時のみ。R04-F11 でドレインを削除した際の判断（「CAS はその確認より前に完了している」）がこの順序では成立していないので、記録として残す |
| L3 | `getSize()` の例外が `ensureCapacity()` の bool 契約から漏れる | 巨大な vector で到達可能。1 行で塞げるが、例外の意味づけを整理してから |
| L4 | `markAsRead()` が読めなかった発行番号を既読にする | `waitFor()` が 1 更新分取りこぼし得る。`subscribe()` には影響しない |
| L6 | 型側 `alignas` で末尾の書き漏らしの窓が広がる | `offsetof`/`sizeof` だけでは原理的に判別できない。ドキュメントに明記する |
| L7 | ビットフィールドを含む型の診断が不親切 | 静的表明で明示する |

ドキュメントの食い違い 21 件と「利用者が踏む穴」10 件は、別途整備する。
